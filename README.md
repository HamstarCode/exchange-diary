# 交換日記アプリ

1対1で交換日記を行うWebアプリ。

## 基本フロー

1. ユーザー生成
2. 交換相手を指定するか、自動マッチングを選択
3. 交換待機
4. マッチング
5. Room生成
6. 日記交換
7. 返信
8. Room解散

## ユーザー

- **nickname**：表示用のニックネーム。変更可能
- **userId**：内部でユーザーを識別するためのID
- **publicUserId**：相手を指定するときに使用する公開ID

ユーザー情報はSupabaseの`users`テーブルで管理する。

## 指定ポケット

交換相手を指定するための機能。

- 指定ポケットに相手がいる → 指定マッチング
- 指定ポケットが空 → 自動マッチング
- 前回の指定は保持する
- 指定相手は変更・削除可能

## マッチング

### 相互指定

```text
A → B
B → A
```

お互いが相手を指定している場合、マッチング成立。

### 一方的な指定

```text
A → B
B → なし
```

一方だけの指定ではマッチングを成立させない。

### 自動マッチング

指定がないユーザー同士は、設定した属性やマッチング条件をもとにマッチングする。

## Exchange

ユーザーが日記を提出すると、Exchangeが作成される。

提出直後は`matching`状態で待機し、マッチングが成立すると`matched`状態になる。

```text
日記を提出
↓
Exchange作成
↓
matching
↓
マッチング成立
↓
matched
```

Exchangeには以下の情報を保存する。

- 自分の日記
- 相手の日記
- 自分からの返信
- 相手からの返信
- マッチング状態
- 指定した相手
- 実際の交換相手

現在はSupabaseの`exchanges`テーブルを使用している。

## 時間

交換には以下の時間制限を設ける。

- 募集時間
- マッチング確定
- 日記を書く時間
- 相手の日記を見る時間
- 返信時間

時間切れになった場合は、その交換状態を終了する。

## Room

マッチング成立時に1対1のRoomを生成する。

交換終了後、Roomを解散する。

## 交換日記

基本的な流れ。

```text
夜
↓
日記を提出（２０時〜
↓
マッチング
↓
翌日
↓
相手の日記を読む
↓
返信する
↓
その日のうちに返信完了（２０時まで
↓
翌日
↓
次の交換へ（２０時〜
```

1交換を、

**「自分の日記 ＋ 相手の日記 ＋ 自分の返信 ＋ 相手の返信」**

の1セットとして管理する。（当日の２０時〜翌日の２０時まで繋がっている）
